A **workspace** is your organization in Shipfox. It holds your members and the
things every team uses: connected tools, runners, model providers, secrets,
and variables.

A **project** is one team, product, or codebase inside the workspace. It owns
its own workflows and its own run history. Most organizations have one
workspace and several projects.

```text
Workspace: acme
|-- Members
|-- Connected tools, runners, model providers, secrets, and variables
`-- Projects
    |-- checkout-api   -> workflows and runs
    |-- mobile-app     -> workflows and runs
    `-- platform       -> workflows and runs
```

## What the workspace holds

Set up a tool once, and every project can use it. Connect GitHub, add a
runner, or store a secret in the workspace, and any workflow in any project
can use it.

The other side of this: a change to a workspace setting reaches every project
that uses it. If you pause a connected tool, every workflow that uses it
stops working. A member of the workspace can see every project in it.

Create a second workspace only when two groups must not see each other's
projects or share any settings.

## What the project holds

A project owns its [configuration](/understand/configuration): the workflows
and actions that run for it. It also owns the runs those workflows produce.
Runs from one project never appear in another.

A project has no settings of its own yet. Every workspace setting applies to
all of its projects, and every member can see all of them.

## Slugs

A workspace and a project each have a short name in URLs, called a slug:
`/w/acme/p/checkout-api/runs`. You can rename a slug. Old links then stop
working, and Shipfox warns you before the rename.

Use [Create a project](/how-to/set-up-work/create-project) to add a project.
[Integrations, integration connections, and
tools](/understand/integrations-connections-and-tools) explains what a
connected tool can do.
