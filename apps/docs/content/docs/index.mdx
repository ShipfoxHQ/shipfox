**Agentic coding makes engineers faster. Shipfox gives them a factory.**

Shipfox is built for engineering teams that already code with AI and want to
delegate work. This ranges from pull request reviews to complex feature
delivery workflows.

You define **workflows** in your repository, combining AI agents with
shell commands. Shipfox orchestrates and runs those workflows, connects them
securely to your tools, and provides full visibility into every run.

[Get started with Shipfox](https://app.shipfox.io). Onboarding in Shipfox
guides the setup. For a closer look at the product, read
[How Shipfox works](/understand).

## Example workflow: from a ticket to a pull request

You choose the engineering work to delegate.
Turning a ticket into a pull request is one example:

1. A ticket labeled for automation starts the work.
2. An agent reads the ticket and changes the code.
3. The agent runs tests. If they fail, it tries to fix the problem.
4. After the checks pass, the workflow opens a pull request.
5. You review the change and decide whether to merge it.

A workflow can also respond to later review comments and continue the work.
You define this behavior, including when automation stops and you step in.

## How it works

### Define your workflow

Choose what starts the workflow, give your agents instructions, and add
commands. Save it as a YAML file in your repository.

### Shipfox runs it

Your tools trigger the workflow. Shipfox checks out your code and runs your
agents and commands.

### Monitor every run

Track progress, inspect agent actions, and monitor costs as workflows run.
Review messages, tool calls, and logs to understand what happened.

## More work to delegate

The same approach fits other recurring engineering work:

- **Dependency maintenance:** assess an update and investigate failing checks
  before you review it.
- **Alert investigation:** examine an error and prepare a diagnosis or a tested
  fix for review.
- **Pull request review:** inspect changes against your guidelines and
  respond to later feedback.

[What teams automate](/what-teams-automate) explains where these workflows
fit and where people participate.

## You set the boundaries

Choose what your agents do and which tools they can use. Decide when they
work on their own and when they need your review.

Review the work in your own tools. [See how Shipfox works](/understand).
