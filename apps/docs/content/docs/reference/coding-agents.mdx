This reference covers the repository files that an agent step reads, the
files it ignores, and the guidance Shipfox adds to every agent step. Both
harnesses, `pi` and `claude`, follow the same rules, except for the order of
instruction files: each harness tries the file its own coding agent reads
first.

## Files an agent step reads

<RepositoryContextFiles />

The repository root is the closest parent of the working directory that
contains `.git`. Without one, Shipfox reads only the working directory.

### Instructions

Shipfox appends the instruction files to the step prompt, after the prompt
text, under the line `Repository instructions; they do not override the task
above:`. Each file starts with its path from the repository root. The step
prompt stays first and takes precedence.

Shipfox does not expand `@path` imports inside an instruction file. An
instruction file below the working directory is not read. The Shipfox system
prompt tells the agent to read it before changing files in that directory.

### Skills

Shipfox lists each skill by its `name` and `description` from the `SKILL.md`
front matter. The agent reads the rest of a skill only when it uses it.

| Rule | Behavior |
| --- | --- |
| Name | The `name` field, or the directory name when the field is missing. |
| Missing description | The skill is skipped. |
| Same name twice | The skill closest to the working directory wins. In the same directory, `.agents/skills` wins over `.claude/skills`. |
| Linked directory | A skill reached through two paths, such as `.claude/skills` linked to `.agents/skills`, loads once. |
| Listed skill not found | The step fails with a configuration error that names the missing skills and the available ones. |

## Files an agent step ignores

Shipfox never reads files that can run code, change permissions, or replace
the system prompt. It also never reads configuration from the runner's home
directory.

| Files | Belongs to |
| --- | --- |
| `.claude/settings.json`, `.claude/settings.local.json`, hooks, `CLAUDE.local.md`, `.claude/CLAUDE.md`, `.claude/rules/` | Claude Code |
| `.mcp.json` | Claude Code and other MCP clients |
| `.pi/settings.json`, `.pi/extensions/`, `.pi/skills/`, `.pi/prompts/`, `.pi/SYSTEM.md`, `.pi/APPEND_SYSTEM.md` | pi |
| `AGENTS.override.md`, `.codex/` | Codex |
| `opencode.json`, `.opencode/`, `.opencode/skills/` | OpenCode |
| `.cursor/rules/`, `.cursor/skills/` | Cursor |
| `~/.claude/`, `~/.pi/`, `~/.agents/`, `~/.codex/` | The runner's home directory |

Agent steps reach external systems through
[integration tools](/understand/integrations-connections-and-tools), not
through MCP servers configured in the repository.

## Compatibility with coding agents

Each row lists the files a coding agent reads in a repository and the part
that an agent step also reads. A file outside the last column is ignored.

| Coding agent | Instruction files | Skill directories | An agent step reads |
| --- | --- | --- | --- |
| Claude Code | `CLAUDE.md`, `.claude/CLAUDE.md`, `CLAUDE.local.md`, `.claude/rules/`. `AGENTS.md` when no `CLAUDE.md` exists. | `.claude/skills` | `CLAUDE.md` and `.claude/skills` |
| Codex | `AGENTS.override.md`, then `AGENTS.md` | `.agents/skills` | `AGENTS.md` and `.agents/skills` |
| OpenCode | `AGENTS.md`, or `CLAUDE.md` when no `AGENTS.md` exists | `.opencode/skills`, `.claude/skills`, `.agents/skills` | `AGENTS.md`, `CLAUDE.md`, `.claude/skills`, and `.agents/skills` |
| Cursor | `.cursor/rules/`, `AGENTS.md` | `.cursor/skills`, `.agents/skills`, `.claude/skills`, `.codex/skills` | `AGENTS.md`, `.agents/skills`, and `.claude/skills` |

## `repository_context`

The `repository_context` field of an agent step turns instructions and skills
on or off. Both are on by default. See
[`steps[*].repository_context`](/reference/workflow-schema#agent-repository-context-fields)
for the accepted values.

This fragment turns repository context off when a pull request comes from a
fork. Add it to an agent step:

```yaml
repository_context: ${{ event.pull_request.head.repo.full_name == event.repository.full_name }}
```

This fragment keeps the instructions and loads only the `code-review` skill:

```yaml
repository_context:
  instructions: true
  skills: [code-review]
```

## What the session shows

Each agent step records a **Repository context** row in its session. The row
lists the instruction files and skills the step loaded. It shows `off` when the
step turned them off and `none found` when the repository has none.
